### PaaS Installation & Add-ons Guide
This guide covers the deployment of core platform-as-a-service (PaaS) components, observability agents, networking integrations, and storage add-ons on top of your OpenShift (OCP) cluster.

#### 1. Monitoring Stack (3-1)
OpenShift provides a pre-configured monitoring stack (built on Prometheus, Alertmanager, and Thanos) to track cluster health, node metrics, and component performance.
```
+-------------------------------------------------------------+
|                     Prometheus Operator                     |
|                                                             |
|   +--------------------+         +----------------------+   |
|   | Prometheus (Scrape)| ------->| Thanos Querier       |   |
|   +--------------------+         +----------------------+   |
|             ^                               |               |
|             | Metrics Collection            v               |
|   +--------------------+         +----------------------+   |
|   | Node Exporter / Kube|        | Grafana Dashboards   |   |
|   +--------------------+         +----------------------+   |
+-------------------------------------------------------------+
```

###### Implementation Steps
1. Verify cluster monitoring operator status:
```
oc get clusterversion monitoring
```
2. Configure user workload monitoring to allow custom application metric scraping by editing the cluster monitoring config map:
```
oc edit configmap cluster-monitoring-config -n openshift-monitoring
```

#### 2. Optional Observability Add-ons (3-3 to 3-6)
2.1 Loki Stack & Cluster Logging (3-3)
Deploys log collection pipelines to aggregate container stdout/stderr logs into persistent object storage or PVCs via the Logging Operator.
```
oc apply -f https://raw.githubusercontent.com/openshift/cluster-logging-operator/master/manifests/
```

2.2 Kiali & Service Mesh (3-4, 3-6)

Service Mesh (Istio-based) manages microservice traffic routing, mutual TLS security, and resilience, while Kiali provides an interactive topology graph and observability dashboard.

  - Key Components Deployed: Istio control plane (ControlPlane), Jaeger for distributed tracing, and Kiali operator.

#### 3. High-Performance Networking & SRIOV (3-7)
Single Root I/O Virtualization (SR-IOV) allows a physical PCIe network device to be shared across multiple virtual machines or pods as direct virtual functions (VFs), bypassing the Linux kernel network stack for ultra-low latency and high throughput.

```
+--------------------------------------------------------+
|                      Worker Node                       |
|                                                        |
|   +-------------+   +-------------+   +-------------+  |
|   |    Pod A    |   |    Pod B    |   |    Pod C    |  |
|   +-------------+   +-------------+   +-------------+  |
|          |                 |                 |         |
|          +--------+--------+--------+--------+         |
|                   | Virtual Functions                  |
|                   v (Direct HW Bypass)                 |
|   +-------------------------------------------------+  |
|   |            SR-IOV Physical NIC Port             |  |
|   +-------------------------------------------------+  |
+--------------------------------------------------------+
```

Apply the SR-IOV network operator node policy to allocate virtual functions:

```Bash
oc apply -f - <<EOF
apiVersion: sriovnetwork.openshift.io/v1
kind: SriovNetworkNodePolicy
metadata:
  name: sriov-nic-policy
  openshift-sriov-network-operator
spec:
  resourceName: intel_sriov_net
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  numVfs: 4
  nicSelector:
    pfNames: ["eth1"]
  deviceType: vfio-pci
EOF
```
#### 4. In-Memory Data Store & Caching: Valkey (3-8)
Valkey provides a high-performance, open-source distributed key-value data store utilized for fast caching, session management, and state storage in cloud-native CNF workloads.

Deploy Valkey via Helm or operator manifests into your target namespace:

```
helm repo add valkey https://charts.valkey.io
helm install valkey-cache valkey/valkey --namespace valkey-system --create-namespace
```
#### 5. Certificate Management & Automation (3-10)
`cert-manager` is a native Kubernetes/OpenShift certificate management controller that automates the issuance, renewal, and management of TLS certificates from internal issuers (like Vault or self-signed CAs) or external issuers (like Let's Encrypt).

```
oc apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.14.0/cert-manager.yaml
```
#### 6. Multus IP Reconciler (3-11)
For CNF (Cloud-Native Network Function) workloads requiring multi-homed networking (such as management, control plane, and data plane interfaces), Multus CNI attaches multiple network interfaces to a single pod. The IP reconciler ensures proper secondary IP address synchronization across interfaces.

Apply the Multus network attachment definition:
```
oc apply -f - <<EOF
apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: sriov-net-1
  namespace: default
spec:
  config: '{
    "cniVersion": "0.3.1",
    "type": "sriov",
    "master": "eth1",
    "ipam": {
      "type": "host-local",
      "subnet": "192.168.100.0/24"
    }
  }'
EOF
```
